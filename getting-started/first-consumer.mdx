A Kafka consumer is any application that reads (subscribes to and processes) messages from one or more Kafka topics. Unlike traditional message queues where a message is removed once consumed, Kafka retains messages for a configurable period and lets any number of consumers read the same data independently — each consumer tracks its own position in the log using an **offset**. This guide covers the console consumer, consumer groups, full code examples in Java, Python, and Node.js, and how to reset or seek to specific offsets.

## Using the Console Consumer

The `kafka-console-consumer.sh` script is the fastest way to inspect the contents of a topic without writing any code. By default it reads new messages as they arrive; add `--from-beginning` to replay everything stored in the topic.

### Reading new messages in real time

```bash
bin/kafka-console-consumer.sh \
  --topic my-first-topic \
  --bootstrap-server localhost:9092
```

The consumer waits silently until a new message is produced. Open a second terminal, start the console producer, type a message, and you will see it appear instantly. Press `Ctrl+C` to stop.

### Replaying all messages from the beginning

```bash
bin/kafka-console-consumer.sh \
  --topic my-first-topic \
  --from-beginning \
  --bootstrap-server localhost:9092
```

### Displaying message keys

By default the console consumer only prints the message value. Add the `print.key` property to see both the key and the value side-by-side.

```bash
bin/kafka-console-consumer.sh \
  --topic my-first-topic \
  --bootstrap-server localhost:9092 \
  --property print.key=true \
  --property key.separator=" | "
```

Example output:

```text
order-1 | {"amount": 99.99, "currency": "USD"}
order-2 | {"amount": 14.50, "currency": "EUR"}
```

## Consumer Groups

A **consumer group** is a set of consumers that collaborate to read from the same topic. Kafka assigns each partition in the topic to exactly one consumer in the group at a time, distributing the read load automatically. When a consumer joins or leaves the group, Kafka **rebalances** the partition assignments.

Assign a consumer to a group using the `--group` flag:

```bash
bin/kafka-console-consumer.sh \
  --topic my-first-topic \
  --group my-consumer-group \
  --bootstrap-server localhost:9092
```

Key points about consumer groups:

- Kafka persists committed offsets for each group in the internal `__consumer_offsets` topic. When a consumer restarts, it resumes from the last committed offset rather than replaying the entire topic.
- If you run the same `--group` command in two separate terminals, Kafka splits the partitions between them — each partition is consumed by only one terminal at a time.
- Multiple independent groups can each read the same topic from the beginning without interfering with each other. This is how you fan-out a single event stream to multiple downstream services.

<Info>
Kafka stores all committed consumer offsets in an internal topic called `__consumer_offsets`. This topic is managed automatically by the broker — you should not produce to it directly. Use `kafka-consumer-groups.sh` to inspect and manage offsets.
</Info>

## Java, Python, and Node.js Consumers

The examples below subscribe to `my-first-topic`, poll for messages in a loop, process each record, and commit offsets after processing.

<CodeGroup>

```java Java
import org.apache.kafka.clients.consumer.ConsumerRecord;
import org.apache.kafka.clients.consumer.ConsumerRecords;
import org.apache.kafka.clients.consumer.KafkaConsumer;
import org.apache.kafka.common.serialization.StringDeserializer;

import java.time.Duration;
import java.util.Collections;
import java.util.Properties;

public class FirstConsumer {

    public static void main(String[] args) {

        // 1. Configure the consumer
        Properties props = new Properties();
        props.put("bootstrap.servers",  "localhost:9092");
        props.put("group.id",           "my-consumer-group");
        props.put("key.deserializer",   StringDeserializer.class.getName());
        props.put("value.deserializer", StringDeserializer.class.getName());
        props.put("auto.offset.reset",  "earliest"); // start from beginning if no offset exists
        props.put("enable.auto.commit", "false");    // commit offsets manually for reliability

        // 2. Create the consumer and subscribe to the topic
        try (KafkaConsumer<String, String> consumer = new KafkaConsumer<>(props)) {
            consumer.subscribe(Collections.singletonList("my-first-topic"));

            // 3. Poll loop — runs until the thread is interrupted
            while (true) {
                ConsumerRecords<String, String> records =
                    consumer.poll(Duration.ofMillis(100));

                for (ConsumerRecord<String, String> record : records) {
                    System.out.printf(
                        "topic=%s partition=%d offset=%d key=%s value=%s%n",
                        record.topic(),
                        record.partition(),
                        record.offset(),
                        record.key(),
                        record.value()
                    );
                }

                // 4. Commit offsets after processing the batch
                if (!records.isEmpty()) {
                    consumer.commitSync();
                }
            }
        }
    }
}
```

```python Python
from confluent_kafka import Consumer, KafkaError

# 1. Configure the consumer
config = {
    "bootstrap.servers":  "localhost:9092",
    "group.id":           "my-consumer-group",
    "auto.offset.reset":  "earliest",   # start from beginning if no offset exists
    "enable.auto.commit": False,        # commit offsets manually for reliability
}

# 2. Create the consumer and subscribe
consumer = Consumer(config)
consumer.subscribe(["my-first-topic"])

# 3. Poll loop
try:
    while True:
        msg = consumer.poll(timeout=1.0)

        if msg is None:
            continue  # no message within timeout window

        if msg.error():
            if msg.error().code() == KafkaError._PARTITION_EOF:
                print(f"Reached end of partition {msg.partition()}")
            else:
                print(f"Consumer error: {msg.error()}")
            continue

        print(
            f"topic={msg.topic()} "
            f"partition={msg.partition()} "
            f"offset={msg.offset()} "
            f"key={msg.key().decode('utf-8') if msg.key() else None} "
            f"value={msg.value().decode('utf-8')}"
        )

        # 4. Commit offsets after processing
        consumer.commit(asynchronous=False)

except KeyboardInterrupt:
    pass
finally:
    # 5. Always close the consumer to trigger a clean rebalance
    consumer.close()
```

```javascript Node.js
const { Kafka } = require("kafkajs");

async function main() {
  // 1. Create the Kafka client
  const kafka = new Kafka({
    clientId: "my-first-consumer",
    brokers: ["localhost:9092"],
  });

  // 2. Create the consumer and connect
  const consumer = kafka.consumer({
    groupId: "my-consumer-group",
  });

  await consumer.connect();

  // 3. Subscribe to the topic
  await consumer.subscribe({
    topic: "my-first-topic",
    fromBeginning: true, // equivalent to auto.offset.reset=earliest
  });

  // 4. Start consuming — eachMessage is called for every record
  await consumer.run({
    eachMessage: async ({ topic, partition, message }) => {
      console.log({
        topic,
        partition,
        offset:  message.offset,
        key:     message.key?.toString(),
        value:   message.value?.toString(),
      });
      // KafkaJS automatically commits offsets after eachMessage resolves
    },
  });
}

main().catch(async (err) => {
  console.error(err);
  process.exit(1);
});
```

</CodeGroup>

## Resetting Offsets

Sometimes you need to reprocess messages — for example after fixing a bug in your consumer logic. Use `kafka-consumer-groups.sh` to reset the committed offsets for a consumer group.

```bash
# Reset all offsets for a group to the earliest available message
bin/kafka-consumer-groups.sh \
  --bootstrap-server localhost:9092 \
  --group my-consumer-group \
  --topic my-first-topic \
  --reset-offsets \
  --to-earliest \
  --execute
```

```bash
# Reset to the latest offset (skip all existing messages)
bin/kafka-consumer-groups.sh \
  --bootstrap-server localhost:9092 \
  --group my-consumer-group \
  --topic my-first-topic \
  --reset-offsets \
  --to-latest \
  --execute
```

```bash
# Reset to a specific offset on a specific partition
bin/kafka-consumer-groups.sh \
  --bootstrap-server localhost:9092 \
  --group my-consumer-group \
  --topic my-first-topic:2 \
  --reset-offsets \
  --to-offset 100 \
  --execute
```

<Warning>
The `--execute` flag applies the reset immediately. Without it, `--reset-offsets` runs in dry-run mode and only prints what it would do. **Stop all consumers in the group before running a reset** — Kafka will refuse to reset offsets while active consumers hold the partition assignments.
</Warning>

You can also reset to a point in time:

```bash
# Reset to the first message produced after a specific timestamp
bin/kafka-consumer-groups.sh \
  --bootstrap-server localhost:9092 \
  --group my-consumer-group \
  --topic my-first-topic \
  --reset-offsets \
  --to-datetime 2024-06-01T00:00:00.000 \
  --execute
```

## Reading from a Specific Offset

For fine-grained control in code, you can skip the group offset entirely and use `seek()` to position the consumer at an exact offset before your poll loop starts.

```java Java — seek example
// After subscribing, wait for partition assignment then seek
consumer.subscribe(Collections.singletonList("my-first-topic"));

// poll(0) triggers partition assignment without returning records
consumer.poll(Duration.ofMillis(0));

// Seek partition 0 of my-first-topic to offset 42
TopicPartition partition0 = new TopicPartition("my-first-topic", 0);
consumer.seek(partition0, 42L);

// Now poll — first record returned will be at offset 42
ConsumerRecords<String, String> records = consumer.poll(Duration.ofMillis(1000));
```

```python Python — seek example
from confluent_kafka import Consumer, TopicPartition

consumer = Consumer({
    "bootstrap.servers": "localhost:9092",
    "group.id":          "seek-demo-group",
})

# Manually assign partitions (don't use subscribe when seeking)
tp = TopicPartition("my-first-topic", partition=0, offset=42)
consumer.assign([tp])

# The next poll will start at offset 42
msg = consumer.poll(timeout=5.0)
if msg:
    print(f"offset={msg.offset()} value={msg.value().decode()}")

consumer.close()
```
