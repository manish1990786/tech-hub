## What is Kafka?

Apache Kafka is an open-source distributed event streaming platform originally developed at LinkedIn and donated to the Apache Software Foundation. At its core, Kafka is a durable, ordered, append-only log that lets you publish and subscribe to streams of events at massive scale. Unlike traditional message queues that delete messages after delivery, Kafka retains events for a configurable period, allowing multiple consumers to replay data independently and at their own pace. Today, more than 80% of Fortune 100 companies rely on Kafka to power their most critical real-time data pipelines.

## Get Up and Running in Three Steps

Follow these steps to have a working Kafka cluster on your local machine and exchange your first messages.

<Steps>
  <Step title="Install Kafka">
    Download the latest Kafka release and extract it, then start ZooKeeper (or KRaft) and the broker with the bundled scripts. All you need is a JDK 11 or later already installed on your machine.

    ```bash
    # Download and extract Kafka
    curl -O https://downloads.apache.org/kafka/3.7.0/kafka_2.13-3.7.0.tgz
    tar -xzf kafka_2.13-3.7.0.tgz
    cd kafka_2.13-3.7.0

    # Start ZooKeeper (required for Kafka broker)
    bin/zookeeper-server-start.sh config/zookeeper.properties

    # In a new terminal, start the Kafka broker
    bin/kafka-server-start.sh config/server.properties
    ```
  </Step>
  <Step title="Create Your First Topic">
    A topic is a named, ordered log where your events live. Create one called `events` with a single partition and a replication factor of one — perfect for local development.

    ```bash
    bin/kafka-topics.sh \
      --create \
      --topic events \
      --bootstrap-server localhost:9092 \
      --partitions 1 \
      --replication-factor 1

    # Verify the topic was created
    bin/kafka-topics.sh --list --bootstrap-server localhost:9092
    ```
  </Step>
  <Step title="Produce and Consume Messages">
    Open two terminals — one to write events into the topic and another to read them back in real time. You'll see messages appear in the consumer the moment you press Enter in the producer.

    ```bash
    # Terminal 1: Start a producer and type messages
    bin/kafka-console-producer.sh \
      --topic events \
      --bootstrap-server localhost:9092

    # Terminal 2: Start a consumer to read messages
    bin/kafka-console-consumer.sh \
      --topic events \
      --from-beginning \
      --bootstrap-server localhost:9092
    ```
  </Step>
</Steps>

## Why Teams Choose Kafka

Kafka's design gives you a set of guarantees that are difficult to achieve with traditional messaging systems. Here are the six properties that make it the industry standard for real-time data.

<CardGroup cols={3}>
  <Card title="Fault Tolerant" icon="shield-check">
    Kafka replicates every partition across multiple brokers. If a broker goes down, a replica is automatically elected as the new leader with no data loss.
  </Card>
  <Card title="High Throughput" icon="bolt">
    Kafka writes sequentially to disk and uses zero-copy I/O, enabling millions of messages per second on commodity hardware with predictable, low latency.
  </Card>
  <Card title="Persistent Storage" icon="database">
    Events are stored durably on disk and retained for as long as you configure. You can replay historical data at any time without re-publishing it.
  </Card>
  <Card title="Consumer Groups" icon="users">
    Multiple independent consumer groups can read the same topic simultaneously, each maintaining its own offset and processing data at its own pace.
  </Card>
  <Card title="Streams API" icon="wave-sine">
    Kafka Streams is a lightweight Java library for building stateful, fault-tolerant stream processing applications that run inside your own JVM process.
  </Card>
  <Card title="Kafka Connect" icon="plug">
    A plug-and-play framework of hundreds of connectors lets you stream data into and out of Kafka from databases, cloud storage, search indexes, and more.
  </Card>
</CardGroup>
